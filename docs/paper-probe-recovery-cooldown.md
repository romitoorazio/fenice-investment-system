# PAPER recovery provider cooldown

The operator recovery workflow waits at least fifteen minutes after the latest execution-market evidence timestamp or canonical PAPER probe/validation run update. Queued, waiting, pending, requested and running canonical cycles block dispatch regardless of age. Both run histories must have valid main-branch schedule/manual/push provenance and explicit UTC creation/update timestamps; missing, future, malformed or inconsistent metadata blocks dispatch. Failed or cancelled runs also count as provider activity because they may have spent credits before failing.

Historical push-triggered canonical cycles, including [24 September run 36052665388](https://github.com/romitoorazio/fenice-investment-system/actions/runs/36052665388), still appear in GitHub's thirty-run history. They count as provider activity without granting permission to dispatch a new cycle. The actual recovery event allow-list and repeat time/provenance check are separate and unchanged.

The cooldown is evaluated by `scripts/paper-probe-cooldown.mjs`, which reads supplied execution evidence and both canonical run lists without calling providers or modifying any dataset. It reports safe timing diagnostics separately from intelligence-quality age. A freshly rebuilt research report can satisfy the existing institutional quality gate without restarting the provider-credit cooldown.

This corrects the observed recoveries on [1 October 2026 at 16:28 UTC](https://github.com/romitoorazio/fenice-investment-system/actions/runs/36892264338) and [2 October 2026 at 15:50 UTC](https://github.com/romitoorazio/fenice-investment-system/actions/runs/37029751245). In both logs, the campaign, source health, quality, daily budget and duplicate/active-run gates passed, but research ages of 1.2 and 2.2 minutes set `cooldown_ready=false`. The execution evidence at those run revisions was dated 30 September at 19:39 UTC and 1 October at 19:04 UTC, respectively, so the recent research update was not an execution-evidence refresh. These were missed dispatch opportunities, not proof that a fill would have occurred.

The daily budget stays at two canonical probe cycles and the one-probe-per-day, human PAPER approval, sizing, independent-source quorum, FX/session, risk, reconciliation, audit, LIVE and broker-connectivity checks remain authoritative in the unchanged canonical workflow. A newer provider-evidence refresh or a recent canonical cycle still blocks recovery for the full fifteen minutes. The recovery trigger repeats its actual-time/event gate immediately before dispatch.

The active V6 fingerprint is preserved: this change only affects the recovery dispatcher, its separate regression workflow, tests and documentation. It neither restarts the campaign nor supplies synthetic evidence or fills. Verify a real weekday recovery after integration; weekend skips alone cannot demonstrate new fill coverage.

Run `node scripts/test-paper-probe-cooldown.mjs`, `node scripts/test-paper-probe-recovery-trigger.mjs` and `node scripts/test-paper-operator-recovery-config.mjs`. The [GitHub CLI run-list contract](https://cli.github.com/manual/gh_run_list) supplies the explicit `createdAt`, `updatedAt`, status, event and branch fields used by the policy.

On trusted main runs, the separate recovery-regression workflow reads current GitHub run metadata and execution evidence and exercises the cooldown CLI without dispatching any workflow, calling a provider or writing PAPER state. Its permissions are limited to Actions and repository read access. Pull requests use local fixtures only.
